# Как работает анализ сметы — пошагово

## Общая схема

```
Пользователь загружает текст/фото/PDF
        ↓
   [Step 1] GPT-4o: Нормализация → структура комнат и работ
        ↓
   [Step 2] GPT-4o: Извлечение работ → список WorkItem[]
        ↓
   [Step 3] Калькулятор (без AI): Цены из базы + материалы
        ↓
   [Step 4] GPT-4o-mini: Итоговая смета + текстовое резюме
        ↓
   Сохранение в БД → Отдача клиенту (с paywall)
```

---

## Step 0. Загрузка файлов

**Файл:** `components/estimate-form.tsx`

- Пользователь вводит текст и/или загружает файлы (PDF, фото, XLSX)
- Фото сжимаются до 1920px/80% JPEG перед загрузкой (`components/file-upload.tsx:14-63`)
- Файлы загружаются напрямую в **Supabase Storage** (bucket `estimate-files`)
- POST на `/api/estimates` с текстом + массивом путей к файлам

## Step 1. Нормализация входных данных

**Файл:** `lib/ai/normalizer.ts`
**Модель:** `gpt-4o` (через OpenRouter), temperature 0.3

Что делает:
- Получает текст пользователя, тексты из PDF (`lib/utils/pdf-parser.ts` — парсинг через `pdf-parse-fork`), изображения как base64
- Отправляет всё в GPT-4o с системным промптом из `lib/ai/prompts.ts:1-33` — AI выступает как "сметчик с 20-летним опытом"
- AI возвращает **структурированный JSON**:

```json
{
  "project_type": "Ремонт квартиры",
  "rooms": [
    {
      "name": "Ванная",
      "area_sqm": 6,
      "ceiling_height": 2.7,
      "works": ["демонтаж плитки", "укладка плитки", "штукатурка"]
    }
  ],
  "total_area_sqm": 65,
  "special_notes": "..."
}
```

## Step 2. Извлечение работ

**Файл:** `lib/ai/extractor.ts`
**Модель:** `gpt-4o`, temperature 0.2

Что делает:
- Получает `NormalizedInput` из Step 1
- Системный промпт (`lib/ai/prompts.ts:35-160`) содержит **каталог из 150+ стандартных работ** по категориям: Демонтаж, Стены, Полы, Потолки, Плитка, Электрика, Сантехника, Двери, Окна, Черновые работы
- Промпт также содержит **правила расчёта объёмов**: площадь стен = периметр × высота потолка − 10% на проёмы, и т.д.
- AI возвращает **массив WorkItem[]**:

```json
[
  { "category": "Плитка", "work": "Укладка плитки на стены", "unit": "м²", "quantity": 28, "room": "Ванная" },
  { "category": "Демонтаж", "work": "Демонтаж плитки", "unit": "м²", "quantity": 28, "room": "Ванная" }
]
```

## Step 3. Расчёт цен (без AI)

**Файл:** `lib/ai/calculator.ts`
**Это чистые вычисления, AI не вызывается.**

Три этапа:

### 3a. Поиск цен в базе

Для каждой работы ищется цена в таблице `price_catalog` (Supabase):
- **Fuzzy matching** (`lib/ai/catalog-match.ts:1-72`): точное совпадение → подстрока (мин 5 символов) → пересечение слов (Jaccard ≥ 0.5, мин 2 слова)
- Стоп-слова фильтруются (русские предлоги, единицы измерения)
- Берётся `price_avg` из каталога

### 3b. Фолбэк-цены

Если работа не нашлась в базе, применяются захардкоженные цены по категориям (`calculator.ts:46-61`):

| Категория | Цена |
|---|---|
| Демонтаж | 200 ₽/м² |
| Электрика | 500 ₽/точка |
| Сантехника | 3000 ₽/шт |
| и т.д. | |

### 3c. Расчёт материалов

Коэффициент материалов зависит от типа работы (`calculator.ts:63-118`):

| Тип работы | Материалы |
|---|---|
| Демонтаж, вынос мусора | 0% |
| Грунтовка, черновая штукатурка | 15% |
| Плитка, ламинат, обои, сантехприборы | 70% |
| Электрика (по категории) | 60% |
| Полы (по категории) | 50% |

**Результат:** `PricedWorkItem[]` — каждая работа с `price_per_unit`, `labor_cost`, `material_cost`, `total`

## Step 4. Генерация итоговой сметы

**Файл:** `lib/ai/generator.ts`
**Модель для резюме:** `gpt-4o-mini`, temperature 0.5

Что делает:
1. **Группирует работы по категориям** в секции (generator.ts:15-28)
2. **Считает итоги**: работы + материалы + **накладные 10%** = итого (generator.ts:30-39)
3. **Оценка уверенности** (generator.ts:42-50):
   - `high` — все комнаты с площадями И 2+ работ в каждой
   - `medium` — частично
   - `low` — ни то, ни другое
4. **AI-резюме** — GPT-4o-mini пишет 3-5 предложений о смете
5. **Авто-предупреждения** — если нет электрики/сантехники или уверенность не высокая

## Paywall при отдаче

**Файл:** `app/api/estimates/[id]/route.ts:58-78`

Когда клиент запрашивает GET `/api/estimates/{id}`:
- Если **не оплачено** и **не админ**: отдаётся только **первые 30% секций** (минимум 1), остальные скрыты
- Добавляются `_hiddenSections` и `_hiddenItems` в ответ
- На клиенте (`components/estimate-result.tsx`) скрытые цены показаны размыто (blur) с CTA "Открыть полную смету — 490 ₽"

---

## Визуально

```
Фото/PDF/текст от пользователя
    ↓
[normalizer.ts]  GPT-4o → "Ванная 6м², Кухня 12м², работы: ..."
    ↓
[extractor.ts]   GPT-4o → [{Плитка, Укладка, м², 28, Ванная}, ...]
    ↓
[calculator.ts]  БД цен + fuzzy match → [{..., price: 1200, labor: 33600, materials: 23520}, ...]
    ↓
[generator.ts]   Группировка + итоги + GPT-4o-mini резюме
    ↓
Supabase DB (status: "ready", result: JSON)
    ↓
Клиент (polling каждые 3 сек) → EstimateResult компонент
```
